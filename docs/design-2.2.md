# ModelLink 2.2 界面设计规格

> 状态：**2026-09-14 定稿**。取代 `docs/design.md`（2.0 冻结版，已被 2.1 跑偏）。
> 设计方向代号 **O「暖白精工」**。

方向选择的原则见 `PRODUCT.md`。本文只写「长什么样」和「为什么」。

---

## 1. 窗口与骨架

- 窗口 **1050 × 700**（3:2），最小 920 × 620，可调大小，启动居中。
  - 定这个尺寸的依据：日志页 7 列的固定宽度合计约 432px，模型名列需 ≥320px，
    964px 内容栏刚好有余量；高度 700 完整显示 8 行数据，再高就是空着。
    1280×800 的小笔记本上仍余 100px 垂直空间（菜单栏 + Dock）。
  - 从 2.1 的 880×640 放大。老用户会察觉，但不至于认不出。
- **取消左侧栏**。导航改为顶部居中的胶囊 tab。
  - 理由：侧栏在 178px 宽度上只承载 4 个导航项 + 一个状态块，密度极低；
    横向 tab 只占 64px 高的顶栏里的一段，把 178px 全部还给内容。
- 结构：**顶栏 64px** + **内容栏 964px 居中**。顶栏左右内边距 43px，与内容栏左缘对齐
  （`(1050 − 964) / 2 = 43`）。
- macOS：隐藏标题栏（`titleBarStyle: "Overlay"` + `hiddenTitle: true`），
  红绿灯悬浮在顶栏左侧；顶栏整条是拖拽区（`data-tauri-drag-region`），
  但导航 tab 与右侧按钮要 `-webkit-app-region: no-drag`。
- Windows：标准标题栏。

## 2. 色板

全局**只有一个强调色**，每页最多用两次。层级靠明度和字重做，不靠色块。

> 而它承载的恰好是列头、「还没测试过连接」、时间戳这类「现在是什么状态」的字；
> 原 `--accent #b8532f` 在淡底上的筛选 chip 只有 4:1。三个值各压深一点，观感几乎不变。

### 深色

**同一套结构，只换变量**，圆角/间距/字阶一行不改。

2026-09-14 重做（原「蓝灰黑 + 暖沙金」被作者判为老套）：底色换成**石墨黑**（近中性、极轻的暖，不带蓝调），
强调色回到和应用图标同一家族的**陶土色**，按钮白字。候选对比过三套（控件黑白 + 陶土只标未应用 / 全用陶土 / 纯黑白），
作者选了全用陶土。

| token | 值 | 备注 |
|---|---|---|
| `--bg` | `#0d0c0b` | |
| `--panel` | `#161514` | |
| `--sunken` | `#111110` | |
| `--hair` | `rgba(255,255,255,.07)` | |
| `--hair2` | `rgba(255,255,255,.12)` | |
| `--fg` | `#efedec` | |
| `--fg2` | `#a9a7a4` | |
| `--fg3` | `#8e8c89` | 面板上 5.4:1 |
| `--accent` | `#df825f` | 文字、描边、选中框：面板上 6.5:1 |
| `--accent-weak` | `rgba(223,130,95,.12)` | |
| `--accent-fill` | `#be573b` | **比 `--accent` 深一档**，白字 4.5:1 |
| `--on-accent` | `#fff` | |
| `--ok` | `#66c093` | |
| `--danger` | `#e47c72` | |
| `--danger-fill` | `#bc4a41` | 白字 5:1 |

**为什么深色要分 `--accent` 和 `--accent-fill` 两档**：深底上的文字要亮才读得清，白字压的色块要深才压得住，
一个陶土色同时满足不了（`#df825f` 压白字只有 3:1）。亮色下陶土红两头都够，所以两个 token 指向同一个值。

**刻意避开「近黑 + 霓虹」**：陶土色不发光、饱和度克制；面板层次靠发丝线 + 顶边一道 3% 白的高光，不靠投影。

服务商头像色在深色下微调（DeepSeek 蓝提亮到 `#3f61ea`、Kimi 黑提到 `#2c2b2a`），
否则纯黑头像在深色面板上糊成一块。

## 3. 字体与字阶

- 拉丁 + 数字：**Archivo**（Omnibus-Type，为标牌与丝印设计的 grotesque，本地打包 woff2 子集）
  - 换掉 2.0 的 Outfit：用得太泛，没有辨识度。
- 中文：`"PingFang SC", "Microsoft YaHei"` 系统栈
- 等宽（技术值）：**Spline Sans Mono** + `font-variant-numeric: tabular-nums`
- **所有技术值一律等宽**：槽位名、模型名、URL、端口、时间戳、token 数、金额、计数

| 角色 | 字号 / 字重 | 字距 |
|---|---|---|
| 页面标题 | 26 / 600 | −0.03em |
| 面板头标题（服务商名） | 15 / 600 | −0.018em |
| 品牌字标 | 15 / 600 | −0.015em |
| 数据主值（模型名） | 14.5 / 600 | −0.012em |
| 摘要大数字 | 21 / 600 | −0.035em |
| 正文 / 设置项 | 13.5 / 500 | −0.01em |
| 表格数据、导航、按钮 | 12.5–13 / 400–600 | |
| 列头、字段标签 | **11** / 600 | +0.05em |

> ⚠️ **11px 是功能性文字的硬下限。**
> 2.0 的字阶里有 9.5px（水印）和 10px（端口、槽位提示），全部废止。
> 交互与内容文字低于 11px，在高分屏上不可读。

| token | 值 |

阴影只有两种，都是中性的，**不许出现彩色辉光**：
- 面板：`0 1px 2px rgba(32,28,24,.05), 0 0 0 1px var(--hair)`

> 彩色辉光（零偏移的同色光晕）读起来是廉价的「发光」，不是被照亮。

## 5. 顶栏（所有页面一致）

```
[logo 26px] ModelLink        [概览|服务商|请求日志|设置]        ● 代理运行中 127.0.0.1:5678  [↻] [+]
```

- 左：26px **应用图标本身**（`src/assets/brand/`，由 `branding/icon-source.png` 裁掉留白生成，不随主题换色）+ 「ModelLink」15/600
  - 不要用图标库的链环图标代替：那不是这个产品的 logo
- 中：**绝对居中**的胶囊 tab 组。激活项白底 + 轻阴影；深色下 6% 白 + 内描边
- 右：运行状态（绿点 + 「代理运行中」+ 端口等宽灰字）、刷新按钮、添加按钮
  - 端口被占时：**红色**、可点击的「代理没在运行 · 换一个端口」，点了跳设置页并选中端口框。
    代理没在跑 = Claude 里每个请求都会失败，不是「提醒」级别；「概览」tab 上的小点也变红。

## 6. 页面规格

### 6.1 概览

页头：「模型链路」+ 副行「这些模型会出现在 Claude Desktop 的模型选择器里。」
右侧**固定放应用按钮**（§7「页头应用按钮」），轻重跟着状态走。状态由下面的连通链来说。

**连通链**（2026-09-14 新增，一块 panel，页头下方）：

```
● Claude Desktop ─────→ ● ModelLink ─────→ ● 服务商              [⋯]
  已接入 · 3 个模型          在运行 · 127.0.0.1:5678    DeepSeek 已连通
```

- 方向就是请求走的方向。每一环：状态点 + 名称 13/600 + 一句状态 12.5；技术值（端口）等宽。
- 两环之间的连线：两端都好是实线，有一端要动手（强调色）或坏了（红）就断成虚线。
- **哪一环有问题，修的按钮就放在那一环上**（小号幽灵按钮）。页头只放应用按钮，两处不会重复。
- `⋯` 菜单：「打开 Claude 配置目录」，Windows 另有「Windows 首次设置步骤」。
  「重新应用」原先收在这里（怕常驻页头引人乱点、打断正在生成的回复）。2026-09-15 作者实测找不到，挪回页头，见 §7。
- 三环的判定写在 `src/lib/health.ts`（`useHealth()`）。**设置页的一键排查读的是同一份**，两处永远说同一句话。

| 环 | 可能的状态 |
|---|---|
| Claude Desktop | 已接入 · N 个模型 / 还没接入 / 有 N 处改动还没应用 / 有 N 处和这里对不上（悬停说明是哪项）/ 端口换了，还没应用 / 费率有更新，还没应用 / 没接到 ModelLink / 没找到它的配置 / 上次应用没成功 / 正在写入 |
| ModelLink | 在运行 · 端口 / **没在运行，端口 N 被别的程序占了**（修：换一个端口） |
| 服务商 | X 已连通 / N 家都已连通 / 还没测试过连接（修：测试连接）/「X」连不上（修：去看看）/「X」还没填 API 密钥（修：去填） |

**模型表**（链下方，唯一的列表）：

| 列 | 宽 | 内容 |
|---|---|---|
| 模型 | flex | 26px 头像 + 模型名 14.5/600 等宽 + 服务商名 12.5 三级色 |
| 上下文 | 78 | 右对齐，`1M` / `256K` |
| 思考深度 | 112 | 右对齐，`可调 · 5 档` / `不可调` |
| 状态 | 96 | 右对齐，5px 圆点 + 「已生效」/「未应用」/「连不上」 |

- **主列是模型真名，不是槽位名。** apply 给每个条目写了 `labelOverride`，新版 Claude 的选择器里显示的就是真名；
  原先的「CLAUDE 槽位 → 实际接入的模型」会让用户去 Claude 里找一个根本不显示的 `claude-opus-5`。
  槽位名只放在行的悬停里。**老版 Claude（不认 labelOverride）** 选择器里显示的是槽位名，这时在行里摊出「Claude 里显示为 claude-opus-5」。
- 状态列：代理没在跑时整列写「连不上」（红）；端口换了还没应用、或 Claude 没指向 ModelLink 时整列「未应用」。
  原先这两种情况下写的是「已生效」—— 典型的「以为 A、实际是 B」。
- **扁平，按槽位顺序排，不分组。** 同一服务商的模型天然连续占槽（展开逻辑是外层遍历服务商）。
- 删掉了「N 个槽位空闲 · Claude 里请求这些名字会直接报错」那一行：空槽根本没写进 Claude，用户碰不到。
- 页脚一行：`n / 20` 个模型 · `m` 个服务商 ⋯ 上次应用 `时间` · 最近请求 `时间`

### 6.2 服务商

页头：「服务商」+ 副行「已添加 `n / 20` 个模型 · 编辑自动保存」；右侧是应用状态（一句话 + 主操作按钮，§7）。

**首次应用之前**，页头下面保留三步条（与引导页同一个组件 `SetupSteps`），高亮当前一步：
挑一个服务商 ✓ → 粘贴 API 密钥（没填 / 正在测试 / 连不上 / 密钥能用）→ 应用到 Claude Desktop。
用户是跟着视频一步步走的，从引导页点进来之后不能就此没了「现在是第几步」。首次应用成功后不再出现。

**服务商 tab 条**（取代 2.0 的 238px 左列）：
- 每项：22px 头像 + 名称 13/600 + 模型数 11.5 三级色 + 连通绿点
- 激活项：1.5px 强调色描边
- 末尾：虚线「+ 添加服务商」
- 理由：典型用户只配 1 家，一整列给一个条目是浪费。改 tab 后编辑区从 ~700px 涨到 964px。

**编辑器面板**：

1. **面板头 56px**（有主语，右侧操作才有落点）：
   `[28px 头像] 服务商名 | ● 已连通 · 14:32 验证 ⋯⋯ [重新测试] [⋯]`
   - 连通状态**常驻**，不是弹一下就消失的 toast。2.0 那版测完弹 toast 就没了，
     用户下次打开完全看不出这个密钥上次通没通。
   - `⋯` 菜单里放「删除服务商」——破坏性操作不和编辑控件混在一起。
2. **字段区**：`API 地址` 与 `API 密钥` **等宽两栏**（`1fr 1fr`，gap 20px），
   同高同形同基线。密钥是密码框 + 眼睛图标。
   - 「API 密钥」标签右侧：「去 X 后台拿密钥 ↗」，打开该服务商官方的密钥页（`presets.ts` 的 `KEY_PAGES`）。
     **只收核实过的地址**，拿不准的那家不给链接。
3. **模型区**：

| 列 | 宽 | 内容 |
|---|---|---|
| 模型 | 262 | **下拉选择器**，不是自由文本框（清单来源写在浮层里，不写进列头） |
| 上下文 | 96 | 只读，来自 models.dev |
| 1M 上下文 | 238 | 开关 + 说明：「已开启」/「可以开」/「最多 256K，开不了」/「清单里没有这个名字」 |
| 在 Claude 里 | flex | **下拉**：这个模型在 Claude 里用的名字，每项写后果（「Auto 模式 · 思考 5 档」/「没有 Auto 模式 · 思考 4 档」），名字放小字；老版 Claude 另外摊出「显示为 claude-opus-5」 |
| （删除） | 32 | × |

   - **模型名改成从清单选**：2.1 已经把 models.dev 的完整模型清单存进
     `models_dev_models`，但 2.1 的界面还在让人手打。下拉里列出这家的可用模型 + 上下文标注，
     底部一行「找不到？直接输入模型名 —— 服务商刚上新时清单可能还没同步到」兜底。
   - **1M 开关自判断**：`claims1mItDoesNotHave()` 已经能算出模型装不装得下 1M。
     装不下时开关**禁用**并写明「最多 256K，开不了」。**在源头拦住，不是等概览页事后标红。**
   - **清单外的名字一直标着**：手敲进来、服务商清单里又没有的模型名，1M 那格写「清单里没有这个名字」。
     有的服务商对错名也回 200、悄悄换成默认模型（CLAUDE.md §二），「测试连接」证明不了它存在，只能常驻标出来。
   - **在 Claude 里用的名字可以换**（2026-09-15 作者提出）：Claude 按名字决定有没有 Auto 模式、能调几档思考，
     走网关时有 Auto 模式的名字只有 4 个（opus-5 / sonnet-5 / opus-4-8 / opus-4-7，核实见 design-2.1 §七⑧），
     模型一多就得由用户决定谁用。规则：
     - 名字**存进配置**（`ModelEntry.slot`），不再按位置现算。原先在前面加一个或删一个模型，后面的全部挪一位 ——
       Auto 模式悄悄没了，Claude 里选着那个名字的对话也换成了别的模型
     - 新加的模型默认拿能力最强的空位；删模型不挪别人的；老配置按原来的位置规则一次性补上，Claude 里什么都不变
     - 下拉**不只列没用过的名字**：选了别的模型正在用的，两个互换（小字写「和「X」互换」），不用先去改另一个腾位置
     - 下拉底部一句：应用之后，Claude 里正选着这个名字的对话会换成新的模型
     - 超出 8 个之后的名字（`claude-ml-N`）Auto 模式还没实测，只写「思考不能调」，不说有没有
     - 名字不进配置哈希；换了要不要应用，看 Claude 那边实际写着的（逐条比 `applied_state`）
4. **面板脚**：**只在有事可做时出现。**
   - 有模型用的名字在 Claude 里不能调思考深度：「这家的模型在 Claude 里不能调思考深度，按这里的默认档来」+ 默认档下拉。
   - 以前设过默认档、现在全都能在 Claude 里选：一句说明 + 「清除」。
   - 全都能在 Claude 里选、也没留旧值：不显示。原先那句「这家的 N 个模型都落在有强度选择器的槽位上」解释的是一个不存在的设置，删了。

### 6.3 请求日志

页头：「请求日志」+ 副行「保留最近 100 条 · 停留在本页时每 2 秒自动刷新」+ 右侧「刷新」

1. **摘要横带 62px**（一行四格，数字与标签同基线）：
   成功率 / 平均耗时 / 今日 token / 今日花费
   - **费率表 2.1 就做好了，2.1 的日志页一个字都没用上。**
   - ⚠️ 「今日花费」遵守 `PRODUCT.md` 原则一：**费率不齐时整格不显示**，换成一句说明，
     绝不估算。
2. **筛选条**：全部 / 仅失败 / 已自动修复 / 按模型，各带计数。
   激活项用强调色描边 + 淡底，不用实心黑药丸（太重）。
3. **数据行 44px**：时间 / 状态点 / 模型名 / 思考档位 / 整流标记 / 耗时 / token 入→出 / 花费 / 状态码
   - 标记用**描边**不用填色药丸：绿描边 = 已自动修复，红描边 = 真出错
   - 标记要写清楚修了什么：「已自动修复 · 思考预算太小」「已自动修复 · 服务商不认思考深度」
   - 后端的 note 原文仍是「已整流 / 未映射槽位」（回归套件与错误响应体按它比对），**只在界面上换说法**（`lib/logs.ts` 的 `NOTE_WORDS`）
4. **失败行下方展开说明**：左缘 2px 红条接住上一行的状态点，正文说人话 + 一个实际出口按钮。
   例（未映射槽位）：
   > **Claude 请求的模型，在 ModelLink 里没有对应**
   > 多半是之前的对话还在用已经删掉的模型。在 Claude 里给这个对话重新选一个模型就行。ModelLink 直接报错，不会悄悄换成别的模型回答。
   > `[看看现在接了哪些模型 →]`

   原先的出口「去服务商页给这个槽位加一个模型」**做不到**：槽位按顺序自动分配，不能指定。

> **需要后端配合**：`LogEntry` 现有字段是 time / model / status / thinking / error / note。
> **耗时、token 数、花费三列是新增字段**，`proxy.rs` 需要记录请求耗时与
> `usage` 里的 input/output token，费用由 `config.rs` 的费率表计算。

### 6.4 设置

分三组，组间用 11/600 三级色小标题分隔：

**常用** —— 一键使用 Winhao 的配置 / 外观（三态 segmented）/ 开机自启 / 软件更新
**高级** —— 代理端口 / 自动同步模型费率
**出问题时** —— 一键排查 / Claude Desktop / 关于

**一键使用 Winhao 的配置**（2026-09-15 新增）：把 Claude Desktop「Configure third-party inference → Workspace」
那一页的开关调成作者日常用的。键、推荐值和起始版本在 `gateway.rs` 的 `WINHAO_PRESET`（逐个对照 app.asar 核实过）。

- 只拨布尔开关，不碰列表类设置（允许的文件夹、工具策略、SSH 白名单）—— 那些是在替用户定范围
- 和 Claude 默认值不同的：打开 Auto 模式、跳过网页抓取的域名检查、高级文件分析；
  其余开关也写成推荐值，用户以前拨过的会被拨回来 —— 所以确认框里逐项列出「会改的 N 项：关 → 开」
- 行上的状态读的是 Claude 那边实际生效的值（没写的键按 Claude 默认值算）：
  「Claude 里已经是 Winhao 的配置」或「和现在有 N 项不同」；用户在 Claude 里自己改过，照实显示
- 装的 Claude 版本不认的键跳过，确认框里单列出来
- 写完重启 Claude（它只在启动时读配置），确认框里写明「会重启 Claude Desktop」
- 一次性写入，不是常驻策略：之后「应用」不会再改这些键，用户在 Claude 里改了也不会被悄悄拨回去
- 还没接入 Claude Desktop（找不到配置文件）时按钮不可用 —— 光有这几个开关、没有网关键的配置文件是残缺的

**一键排查**（新增）：用户在 Claude 里报错时第一反应就是来设置页翻，2.1 这里什么都没有。
三个 chip，就是概览页连通链的三环（读同一份 `useHealth()`）：`Claude Desktop：…` `ModelLink：…` `服务商：…`。
有修法的 chip 可点。「开始检查」= 重读代理 / Claude 配置 + 把所有服务商真测一遍。
（原先四项里「配置已生效」和「端口被占用」可以同时一绿一红 —— 现在「要不要应用」归在 Claude 那一环里说。）

端口被占时，「代理端口」那一行的说明变红：「端口 5678 被别的程序占了。换一个 1024–65535 之间的数字，比如 5679，再应用一次」。

「Claude Desktop」行加「打开配置目录」——真出问题时要用户把配置发过来，
不能让他们自己去找 `~/Library/Application Support/Claude-3p/`。

### 6.5 首次启动（零服务商）

概览页变引导页。

1. 页头：「选择一个服务商开始」+「配置 API 密钥后，一键接入 Claude Desktop。全程三步，大约两分钟。」
2. **三步说明条**（新增）：挑一个服务商 / 粘贴 API 密钥 / 应用到 Claude Desktop，各带一句话

## 7. 应用状态机

| 态 | 判定 | 服务商页页头右侧（一句话 + 按钮） |
|---|---|---|
| clean | 不欠 Claude 任何东西（见下） | 绿勾「配置已生效」；改过但当场生效的是「已保存，立即生效」。幽灵按钮「重新应用」，**强调色一次都不用** |
| dirty | 欠 Claude 东西 | 强调色一句原因 +「会重启 Claude Desktop」+ 实心按钮「应用到 Claude Desktop」 |
| applying | apply 进行中 | 按钮内 spinner + 「正在重启 Claude…」，全局禁止再次触发 |
| error | apply 失败 | 红字摘要 + 「重试」 |

**dirty 看的是 Claude 那边真正写着的东西，不是配置哈希**（2026-09-14 改）：
- 槽位 / 显示名 / 1M 对不上（前端拿 `applied_state` 逐条比）
- 网关没指向这个代理、**端口在上次应用之后换过**、写进去的费率表过期（后端 `pending_apply`，
  费率用写入时的同一个函数生成再逐值比）
- Claude 设置页里改得动、改掉就坏事的两项（后端 `pending_apply`，2026-09-15 加）：「允许联网的域名」不再放行全部
  （Cowork、Code 里抓网页和装包会 403）、模型身份说明没了（模型可能自称 Claude）。
  改掉之后模型列表照样对得上、界面一切正常 —— 不查就是「以为 A、实际是 B」。
  **只看会不会坏事，不逐字比**：列表里还有 `*` 就算放行全部；说明前后加了别的话，代理照样认得出（和转发时认说明用同一组首尾句）。
  Claude 那一环写「有 N 处和这里对不上」，悬停说明是哪项、会坏什么
- 只改了密钥 / 地址 / 默认档：代理当场就用上了，**不算 dirty**，不必为此重启一次 Claude
- 端口单独记：`set_port` 会立刻改写配置文件里的地址，文件对得上也不代表 Claude 用上了（它要重启才读），
  所以 apply 时把端口记进 `last_applied_port`（后端专管，**不进 canonical hash**，老用户升级不会变脏）
- `last_applied_port` 为空（2.2 之前应用的 / 从没应用过）时退回按哈希判断，宁可多提示一次；应用一次之后就按上面的规则

**页头应用按钮**（概览页、服务商页都**一直在**，按这个优先级取第一个）：
1. 正在应用 → 「正在重启 Claude…」（禁用）
2. 有服务商没填完 → 「应用到 Claude Desktop」**灰掉**，旁边写「先填好「X」的 API 密钥」这类
   —— 应用一定会失败。原先密钥还空着「应用」就亮着，点了报「还没填 API 密钥」，配的按钮却是「重试」
3. 上次应用失败 → 实心「重试」
4. dirty → 实心「应用到 Claude Desktop」+「会重启 Claude Desktop」；代理没在运行时降成幽灵按钮，先换端口
5. 都没有 → 幽灵按钮「重新应用」+「会重启 Claude」

- **修的按钮**（换一个端口 / 去填 API 地址 / 去填 API 密钥 / 去选模型 / 测试连接）：概览页放在连通链出问题的那一环上；
  服务商页没有链，放在应用按钮左边，间距比「会重启 Claude」和它的按钮之间大，免得那句话被看成在说修的按钮。
- **为什么一直在**（2026-09-15 改）：原先页头只放「现在最该做的一件事」—— 没填完时换成「去填 API 密钥」，没改动时不放，
  「重新应用」收在 ⋯ 菜单里。作者实测：看着「有 2 处改动还没应用」，到处找不到应用按钮。核心操作要有固定的位置，
  怕人乱点的顾虑用「没改动时是幽灵按钮 + 旁边写会重启」来压。

- 概览页数据行的 dirty 表达：**行左缘 2px 强调色竖条** + 状态列写「未应用」+ 头像淡一档。不喊，但躲不掉。
- 自动保存：任何编辑 400ms 防抖写盘，无保存按钮，写盘失败 toast 报错。
